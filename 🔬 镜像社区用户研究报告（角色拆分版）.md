### 三、每一步的信息需求分析

#### ❶ 触发 — "我要跑个 XX"

| 信息需求                   | 当前现状                        | 问题                       | 设计机会                              |
| -------------------------- | ------------------------------- | -------------------------- | ------------------------------------- |
| 镜像社区入口在哪？         | 藏在「创建实例 → 社区镜像 Tab」 | 新用户根本不知道有镜像社区 | 顶导航增加「镜像广场」独立入口        |
| 我能用中文描述需求吗？     | 只能搜英文镜像名                | 小白不知道 ComfyUI 这个词  | 搜索支持场景描述："AI 绘图""做数字人" |
| 有没有教程告诉我该选什么？ | 无引导                          | 无从下手                   | 场景化入口卡片："我要画图" "我要训练" |

**小白用户的第一印象至关重要**：他不会自己找路径，需要在进入平台的前 10 秒就看到「镜像社区」这个概念，并理解它 = "别人帮你配好环境，你直接用"。

#### ❷ 发现 — "有没有现成的镜像？"

| 信息需求       | 优先级 | 小白关注点                           | 设计建议                                                 |
| -------------- | ------ | ------------------------------------ | -------------------------------------------------------- |
| 按任务场景分类 | 🔴 最高 | "我不知道框架名，但我知道我要做什么" | 一级导航按场景：绘图 / 数字人 / LLM / 语音 / 视频 / 训练 |
| 搜索           | 🔴 最高 | 用中文搜、用场景描述搜               | 支持模糊匹配 + 别名（"AI画图" → ComfyUI / SD-WebUI）     |
| 热度排行       | 🟡 高   | "大家都在用什么？跟着选就行"         | 显著展示「部署量」排序，Top 10 加「热门」标签            |
| 官方推荐       | 🟡 高   | "官方背书的应该靠谱"                 | 「官方精选」区域独立展示，配「✓ 优云精选」Badge          |
| 新上架通知     | 🟢 中   | "有没有新东西？"                     | 「本周新品」卡位                                         |

**关键洞察**：小白的发现路径是 **场景驱动** 而非技术驱动。他不会搜 "PyTorch 2.1 + CUDA 12.1"，他会搜 "跑 Stable Diffusion 的镜像"。

#### ❸ 评估 — "这个靠谱吗？"

这是小白用户 **最大的决策瓶颈**。他缺乏技术判断力，完全依赖外部信号来建立信任。

| 信任信号          | 优先级 | 小白怎么看             | 设计建议                                 |
| ----------------- | ------ | ---------------------- | ---------------------------------------- |
| 部署次数（Pulls） | 🔴 最高 | "8000 人用过 = 靠谱"   | 卡片上醒目展示，用「已部署 8.1k 次」表述 |
| 社区评分（Stars） | 🔴 最高 | "4.8 分 = 好用"        | 五星制评分，展示在镜像名旁边             |
| 官方认证 Badge    | 🔴 最高 | "官方认的 = 放心"      | 「✓ 优云精选」蓝色 Badge                 |
| 最近更新时间      | 🟡 高   | "3天前更新 = 有人维护" | 卡片底部：「最近更新：3 天前」           |
| 用户评论/评价     | 🟡 高   | "看看别人怎么说"       | 详情页有评论区，卡片上标「xx 条评价」    |
| 适配 GPU 标签     | 🟡 高   | "我的卡能跑吗？"       | 醒目标注「推荐 4090 · 最低 12G 显存」    |
| 创作者身份        | 🟢 中   | "这人是谁？"           | 显示创作者头像 + 名称，点击进主页        |
| 镜像大小          | 🟢 中   | "要等多久？"           | 标注大小，注明预计拉取时间               |

**关键洞察**：小白做决策靠的是 **社会证明**（多少人用了）+ **权威背书**（官方精选）+ **时间信号**（最近还在更新），而不是技术参数。

### 三、每一步的信息需求分析

#### ❶ 制作 — 保存实例为镜像

| 信息需求             | 当前现状             | 问题                 | 设计建议                                                |
| -------------------- | -------------------- | -------------------- | ------------------------------------------------------- |
| 从哪个实例保存？     | 控制台实例列表中操作 | 入口不直观           | 实例操作菜单中醒目标注「发布为社区镜像」                |
| 系统盘会完整打包吗？ | 是，但文档里才能查到 | 创作者担心数据泄露   | 发布前增加「打包预览」：列出将包含的文件/目录，支持排除 |
| 镜像大小预估？       | 不可见               | 不知道会产生多大镜像 | 保存前提示预估大小，建议清理缓存                        |

#### ❷ 发布 — 填写镜像信息

**信息优先级排序（发布流程）**：

| 优先级      | 字段                | 原因                           |
| ----------- | ------------------- | ------------------------------ |
| P0 必填     | 镜像名称            | 身份标识                       |
| P0 必填     | 一句话描述          | 消费者卡片上最先看到的文字     |
| P0 必填     | 场景标签            | 消费者发现路径的核心筛选维度   |
| P0 必填     | 推荐 GPU + 最低显存 | 消费者评估环节的核心信任信号   |
| P1 强烈建议 | 封面截图            | 有截图的卡片点击率远高于纯文字 |
| P1 强烈建议 | 使用说明            | 消费者详情页确认环节的关键信息 |

| P2 可选     | 端口/启动命令       | 高级配置                       |
| P3 可选     | 环境变量            | 特殊场景                       |

**关键设计原则**：
- **技术规格尽量自动提取**，别让创作者手动填 CUDA 版本
- **提供填写模板**，降低「我不知道该写什么」的认知负担
- **提交前预览**，让创作者看到消费者视角的效果

### 四、关键设计原则总结

| #    | 原则                   | 消费者体现                                                   | 创作者体现                                                   |
| ---- | ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 1    | **信息分层，渐进披露** | 先看"能做什么"，再看"靠不靠谱"，最后看"技术细节"             | 先填必填项，自动提取技术信息，可选项折叠                     |
| 2    | **降低决策成本**       | 社会证明（部署数）+ 权威背书（Badge）+ 同伴验证（评分）      | 数据看板给出行动建议（"你的镜像描述不完整，完善后曝光提升 40%"） |
| 3    | **用用户语言**         | "AI 绘图"而非"SD-WebUI"，"至少 24G 显存"而非"VRAM ≥ 24576MB" | "已被 8000 人使用"而非"pulls: 8000"                          |
| 4    | **闭环反馈**           | 用了 → 能评价 → 看到别人评价                                 | 发了 → 看到数据 → 有人评论 → 能互动                          |
| 5    | **降低创作门槛**       | N/A                                                          | 自动提取技术规格、提供填写模板、支持 Fork 衍生               |
| 6    | **建立社区信任**       | 认证体系 + 评分 + 评论                                       | 创作者认证 + 主页 + 累计贡献                                 |

---

> 🎯 **核心洞察**：消费者和创作者的关系是一个**飞轮**——消费者用得多 → 数据反馈让创作者有成就感 → 创作者更积极维护和发布 → 社区镜像质量提高 → 更多消费者愿意用。当前飞轮卡在两个地方：消费者**缺乏信任信号**所以不敢用社区镜像，创作者**缺乏数据反馈**所以没动力维护。改版需要同时打通这两个卡点。
