## 一、产品定位与目标用户

### 目标用户
公司市场部/品牌部同事，非专业设计背景，日常需要高频产出线下物料，但不具备设计工具操作能力。

### 典型痛点
- **工具门槛高**：Figma/PS/AI 学习成本高，即使装了软件也做不出像样排版（字体搭配、间距、对齐这些设计常识不掌握）。
- **设计师资源稀缺、排期慢**：一个易拉宝、一张海报这种"小需求"也要走设计师排期，常等 1-2 天，而市场活动经常"今天要明天用"。
- **临时性/高频/低复杂度需求被长期忽视**：展会易拉宝、活动宣传页、内部通知——量大但单个价值低，专业设计师投入产出比低，长期被糊弄（用 PPT 拼一个了事）。
- **反复修改成本高**：文案改一版、日期改一版，若还要找设计师改源文件，来回沟通成本高。

### 核心价值主张
- **"输入一段话，30 秒内拿到一版可用设计稿"**——把"表达需求"到"看到设计"的距离缩短到自然语言/结构化表单输入。
- **"所见即所得的二次编辑"**——区别于 Midjourney 类工具生成完就是像素图不可改，本工具生成后仍可精确调整文字/颜色/布局，操作难度对标"改 PPT"而非"用 Figma"。

产品定位：**面向非设计师的、"生成式起点 + 结构化精调"的自助设计工具**，区别于纯 AI 出图工具（不可编辑）和专业设计软件（学习成本高）。

### 非目标（显式排除，管理预期）
- 不追求替代专业设计师做品牌级视觉创意（大型 campaign KV、复杂海报）。
- 不追求 Figma 级别的自由创作能力，编辑器功能定位为"够用的精调"，不是"从零设计"。

## 二、核心用户故事与使用流程

### 主流程
1. **输入需求**：选择物料类型（展板/易拉宝 或 宣传页）→ 选择尺寸规格 → 填写文案要点（标题/副标题/正文/活动信息等结构化字段，非单一大文本框）→ 选择风格标签（科技感/简约/活泼/商务）→ 可选上传品牌素材（Logo、产品图）。
2. **澄清确认（Clarify）**：AI 基于用户已填信息，识别缺失/模糊的关键字段（如未指定主色调、文案信息不全、风格描述含糊），以**追问的形式**逐项向用户确认（例如"要展示的产品图有吗？没有的话用图库配图可以吗？""主标题字数较多，是否需要精简？"）。追问采用结构化多选/简答，尽量减少用户手动打字。**全部关键信息确认完毕后，用户点击"开始生成"才进入生成阶段**——这一步是本产品与"一言生成"类工具的关键差异化设计，用信息完整度换取生成成功率。
3. **生成**：AI 基于已确认信息，**生成单一方案（1个画板）**，而非多候选方案墙。
4. **编辑/继续生成**：用户在画布上对生成结果进行操作，见下方"画板选中态"逻辑。
5. **导出**：选择格式（PNG/PDF，可选HTML）与分辨率/出血设置 → 生成文件 → 下载。

### 画板选中态：决定"重新生成"的作用范围
这是本产品的核心交互约定，需要在编辑器里保持一致：
- **选中某个画板时**：点击"重新生成/AI调整"等操作，作用范围是**当前选中的画板**——基于该画板已有内容+用户新的修改指令，做增量调整（如换个背景风格、调整某段文案），保留用户已做的编辑成果，不推倒重来。
- **未选中任何画板时**：点击"生成"，视为**新建一个独立画板**，走完整的需求输入+澄清确认+生成流程，与已有画板互不影响。
- 用户可在同一个工作区内积累多个画板（对应多个物料版本/变体），画板依次排列在同一块无限画布上，通过平移/缩放画布查看和切换编辑对象，但每次生成动作本身只产出一个结果，不再有"多方案墙"这一中间态。

### 关键交互点与边界情况
- **生成不满意**：在选中该画板的状态下，用自然语言描述想要的调整（"背景换成蓝色调""标题再大一点"），触发针对该画板的**增量重新生成**；也支持"局部重新生成"（只重绘某个区域/图层，保留其余排版）。
- **澄清问题过多导致用户不耐烦**：需要控制单轮追问数量上限（建议一次不超过 3-4 个关键问题），非必要字段允许"跳过，用默认值"，避免澄清环节本身变成新的门槛。
- **文字溢出/图层重叠等排版异常**：需要"生成后自动校验+自动修正"兜底逻辑（见第四节）。
- **图片来源缺失**：属于澄清确认环节需要追问的典型场景之一——若用户未上传素材，提前询问是否接受图库配图/AI生成图，而非生成后才让用户发现图不对。
- **撤销/重做**：基础但必须有，防止误操作导致用户流失信任。
- **中途更换尺寸/物料类型**：属于"结构性变更"，视为对当前选中画板的重新生成请求（走一次简化版澄清确认，仅确认新尺寸下受影响的关键字段），而非自动拉伸缩放。
- **保存与草稿**：自动保存 + 历史画板留存在同一工作区画布上，避免流程被打断后工作丢失。

## 三、功能范围（MVP / 二期 / 远期）

### MVP（第一阶段）
- 物料类型：展板/易拉宝（竖版尺寸预设：60×160cm、80×180cm、90×200cm）、宣传页/DM单（A4/A5，横竖版）。
- AI 生成：结构化表单输入 + 风格标签选择 + **澄清确认对话（信息补全后再生成）+ 单方案生成**。
- 画布编辑器：文字编辑（内容/字号/字体/颜色/行距/字距）、图层拖拽移动/缩放/旋转、间距调整、颜色调整（取色器+品牌色预设占位）、图片替换（上传）、图层增删（基础形状/文本框/图片框新增，图层顺序/对齐/分布）。
- 导出：PNG（含分辨率/DPI选项）、PDF（含出血/裁切线，面向印刷场景）。
- 基础模板库/风格库：作为生成失败兜底 + "直接选模板起步"的备选路径。

### 二期
- 手册类多页文档支持（跨页版式一致性、页面管理UI，复杂度显著高于单页物料，需独立评估）。
- HTML 导出（结构化图层+DOM渲染架构天然具备低成本导出能力，优先评估）。
- 协作与分享（多人查看/评论，非同时协同编辑起步）。
- 品牌规范锁定：企业色板、Logo库、指定字体，作为AI生成的约束条件注入，提升"每次生成都符合品牌调性"的稳定性——企业级推广的关键卖点。
- 历史版本管理（版本对比、回滚）。

### 远期
- Figma 文件导出（技术复杂度高，见第六节）。
- 更多物料类型（桌牌、工牌、背景板KV、公众号封面等）。
- 团队协作评审流程（提交审批、多角色权限）。

> **关于 HTML 导出为何不放进 MVP**：渲染层本身就是结构化图层→DOM/CSS，导出静态HTML边际成本低，但 (1) MVP 阶段核心目标是验证"生成质量+编辑体验"这个产品假设，HTML导出不是市场部核心诉求（他们要能打印/能发的图或PDF）；(2) 资源应优先投入生成质量打磨。作为"低成本高杠杆"功能放二期开头即可，不应抢占 MVP 验证窗口。

## 四、详细功能说明与交互原型示意

本节把第二、三节的流程和范围落到具体界面结构，用于团队评审时对齐交互细节。原型为线框示意（非最终视觉稿），核心是把控件位置、状态、异常提示等交互逻辑讲清楚。

### 4.0 整体界面布局

**左右双栏布局，贯穿从需求输入到编辑的全流程，不做"表单页→编辑页"的页面跳转**：
- **左侧：无限画布区**——占屏幕主要面积，用于承载所有画板（Artboard）。初始为空画布，随着用户新建设计，画板依次在画布上排列，可自由缩放/平移查看。这一区域同时承担"生成结果展示"和"精细编辑"两个职责。
- **右侧：AI 对话区**——固定宽度侧边栏，是**需求输入、澄清确认、生成指令、增量调整**这一整条链路的统一入口，全程以聊天消息形式呈现（用户消息 + AI 消息 + 内嵌的结构化控件如选项按钮/表单卡片）。用户不需要在"填表单"和"聊天"之间切换心智模型，两者是同一个对话流的不同消息类型。
- **图层属性调整（字号/颜色/间距等）不占用固定第三栏**，而是以**浮动工具条/上下文面板**形式出现：选中画布上某个图层时，在该图层附近浮现一个精简工具条（常用属性：字号/颜色/加粗/对齐）；点开工具条上的"更多"或双击图层，才展开更完整的属性面板（浮层卡片，覆盖在画布上，不挤压画布空间）。这一设计选择的理由：保持画布区域最大化可用，贴近 lovart/stitch 类工具"内容为中心"的简洁感，也避免非设计师用户面对常驻的专业属性面板产生压迫感。

```
┌──────────────────────────────────────────┬─────────────────┐
│  顶部工具栏：撤销/重做  缩放  导出            │  AI 对话区         │
├──────────────────────────────────────────┤─────────────────┤
│                                            │ 🤖 你好，想做什么   │
│         无限画布区                          │    类型的物料？     │
│                                            │                   │
│   ┌──────────┐      ┌──────────┐          │ 我  展会易拉宝       │
│   │  画板1     │      │  画板2     │          │                   │
│   │ (选中态高亮)│      │           │          │ 🤖 [结构化追问/    │
│   └──────────┘      └──────────┘          │    表单卡片]        │
│      ▲ 浮动工具条                          │                   │
│      (选中图层时出现)                       │ 我  [输入/选择回复]  │
│                                            │                   │
│                                            │ ──────────────── │
│                                            │ [输入调整指令…]  ➤ │
└──────────────────────────────────────────┴─────────────────┘
```

### 4.1 需求输入（对话区内的表单卡片）

用户点击"新建设计"后，AI 对话区以**表单卡片消息**的形式引导用户填写关键信息，而非跳转到独立表单页面——卡片作为一条 AI 消息出现在对话流中，用户在卡片内填写后提交，即成为对话流中的一条"用户消息"。

| 功能点 | 交互说明 | 异常/边界处理 |
|---|---|---|
| 物料类型选择 | 卡片内单选，切换后卡片内尺寸选项联动切换 | — |
| 尺寸规格 | 下拉预设尺寸（如展板类：60×160/80×180/90×200cm），支持"自定义尺寸"输入 | 自定义尺寸超出常见印刷范围时提示确认 |
| 文案字段 | 分字段结构化输入：主标题/副标题/正文卖点/活动时间地点/联系方式，而非单一大文本框 | 字段过长时右下角字数提示，不做强制截断（留给澄清环节处理） |
| 风格标签 | 多选标签（科技感/简约/活泼/商务），非自由文本描述 | 未选择时使用行业默认风格 |
| 品牌素材上传 | Logo/产品图上传，支持拖拽 | 未上传不阻塞提交，转交澄清环节确认 |

```
┌─────────────────────────┐
│ 🤖  先告诉我一些基本信息：    │
│ ┌─────────────────────┐ │
│ │ 物料类型：○展板 ○宣传页  │ │
│ │ 尺寸：   [80×180cm ▾]  │ │
│ │ 主标题： [__________]  │ │
│ │ 副标题： [__________]  │ │
│ │ 正文卖点：[__________]  │ │
│ │ 活动信息：[时间][地点]   │ │
│ │ 风格：  [科技][简约]... │ │
│ │ 素材：  [传Logo][传图]  │ │
│ │           [ 提交 ]     │ │
│ └─────────────────────┘ │
└─────────────────────────┘
```

### 4.2 澄清确认对话

表单提交后，AI 在同一对话流中继续以消息形式追问缺失/模糊信息，用户直接在对话区内逐条回复，无需离开对话区。

| 功能点 | 交互说明 | 异常/边界处理 |
|---|---|---|
| 追问形式 | 聊天式逐条展示，优先单选/简答，减少手动打字 | 单轮追问数量上限3-4个，超出的次要问题合并到编辑阶段再问 |
| 必填 vs 选填 | 关键字段（如缺失联系方式）必须回答才可继续；次要字段可"跳过，用默认值" | "开始生成"按钮在必填项未确认前置灰 |
| 进度提示 | 对话区顶部显示"3/4"类进度，让用户预期还剩多少问题 | — |

```
┌─────────────────────────┐
│ 进度 3/4                  │
│ 🤖 没有产品图，用图库配图    │
│    可以吗？                │
│    ○可以，帮我配图 ○我再传  │
│                           │
│ 🤖 主标题较长，建议精简为   │
│    一行，可以吗？           │
│    ○可以精简  ○保持原样    │
│                           │
│ 🤖 活动地点信息缺失，能补   │
│    充一下吗？               │
│    [________]  [跳过]     │
│ ──────────────────────  │
│         [ 开始生成 → ]     │
└─────────────────────────┘
```

### 4.3 生成等待态

信息确认完毕后触发单方案生成。等待反馈**同时出现在两处**：对话区内 AI 消息给出文字进度说明，画布区对应位置出现骨架屏占位（预示画板即将生成的位置和大致尺寸），二者呼应，让用户清楚"生成结果会出现在画布的哪里"（呼应第九节"性能与延迟"风险）。

```
左侧画布区：                       右侧对话区：
┌──────────┐                    ┌─────────────────┐
│ ░░░░░░░░░ │ ← 骨架屏占位          │ 🤖 正在设计中…      │
│ ░░░░░░░░░ │   (画板即将出现的位置)  │    ▓▓▓▓░░░░ 60%   │
│ ░░░░░░░░░ │                    │    正在排版文案与素材 │
└──────────┘                    └─────────────────┘
```

### 4.4 主编辑器界面（核心：画板选中态）

生成完成后，画板出现在左侧画布区，右侧对话区持续在线，可随时针对当前选中画板发起调整指令。**当前是否选中某个画板，决定对话区发出的指令作用范围**——这是第二节交互约定在界面上的落地，需要给出清晰的视觉区分（画布上选中态高亮框 + 对话区输入框上方提示当前作用对象）。

```
┌──────────────────────────────────────────┬─────────────────┐
│ 顶部工具栏：撤销/重做  缩放  导出            │  AI 对话区         │
├──────────────────────────────────────────┤─────────────────┤
│   ┌──────────┐      ┌──────────┐          │ 历史对话消息…       │
│   │▓▓选中态▓▓│      │  画板2     │          │                   │
│   │  画板1     │      │           │          │                   │
│   │ ⤢ 🔄 🎨 T │←浮动工具条         │                   │
│   └──────────┘      └──────────┘          │ ──────────────── │
│                                            │ 正在调整：画板1 ✓  │
│                                            │ [输入调整指令…]  ➤ │
└──────────────────────────────────────────┴─────────────────┘
```

**选中态对比示意**（对应第二节"画板选中态"逻辑）：

```
选中画板1时：                          未选中任何画板时（点击空白画布区）：
画布：画板1出现高亮选中框                画布：所有画板均无高亮
对话区输入框上方提示：                   对话区输入框上方提示：
  "正在调整：画板1"                       "新建设计"（或为空/引导语）
输入调整指令 → 增量修改画板1              输入需求描述 → 走完整流程新建画板
```

### 4.5 图层编辑操作（浮动工具条 + 上下文面板）

选中画布上的某个图层（非画板本身）时，在该图层附近浮现一个精简工具条，承载最高频的属性调整；更完整的属性（如详细行距/字距/阴影）通过点击工具条"更多"展开为浮层卡片，覆盖在画布上方，不常驻挤占画布空间。

| 功能点 | 交互说明 | 异常/边界处理 |
|---|---|---|
| 图层选中 | 单击选中单个图层，Shift+单击多选；选中后图层上方/附近浮现精简工具条 | 图层选中态与"画板选中态"是两层概念，需视觉区分（图层浮动工具条 vs 画板高亮边框） |
| 浮动工具条常用属性 | 文本图层：字号/颜色/加粗/对齐；形状图层：填充色/描边/圆角；图片图层：更换图片/裁剪 | 工具条随图层拖拽跟随移动，避免遮挡被编辑内容本身 |
| 更多属性面板 | 点击工具条"…更多"或双击图层，展开浮层卡片（行距/字距/透明度/阴影等完整属性） | 浮层卡片可拖动定位，避免遮挡画布关键区域 |
| 拖拽/缩放/旋转 | 选中后出现控制点，拖拽时显示对齐辅助线（吸附其他图层边缘/画布中心线） | 超出画布边界时给出视觉提示（半透明遮罩），不强制阻止 |
| 文本编辑 | 双击进入编辑态，浮动工具条同步字号/字体/颜色控件 | 文字溢出容器时高亮容器边框提示，用户可手动调整或触发"自动缩小字号"建议 |
| 图片替换 | 选中图片图层后浮动工具条出现"更换图片"入口，弹出"上传/图库检索/AI重绘"三个选项 | 与澄清阶段的图片来源策略呼应，编辑阶段仍保留同样三个入口 |
| 图层增删 | 画板右键菜单/顶部工具栏"+"新增基础形状/文本框/图片框；选中图层右键删除 | 因不设常驻图层树面板，图层管理（显示/隐藏/排序）作为浮层卡片的一个入口，二期可评估是否需要独立图层面板 |

### 4.6 导出

导出入口放在顶部工具栏（画布区上方），点击后弹出导出设置浮层，不经过对话区：

```
│  导出                                        │
├────────────────────────────────────────────┤
│ 格式：   ☑ PNG   ☑ PDF   ☐ HTML(二期)         │
│ PNG设置： 分辨率 [ 高清(300dpi) ▾ ]             │
│ PDF设置： ☑ 含出血线  ☑ 含裁切线                 │
│                              [ 生成并下载 ]    │
└────────────────────────────────────────────┘
```

| 功能点 | 交互说明 | 异常/边界处理 |
|---|---|---|
| 格式多选 | PNG/PDF 可同时勾选批量导出 | HTML 二期开放前置灰+"敬请期待"提示 |
| PDF 印刷参数 | 出血线/裁切线用图示+大白话说明（如"用于送印刷厂，网上分享不需要勾选"），不直接暴露"CMYK/出血mm"等术语 | 呼应第九节"印刷专业门槛"风险，需产品文案专门打磨 |
| 导出进度 | PDF走服务端渲染有排队等待，需展示进度而非无反馈等待 | 服务端渲染失败时提供"重试"和"降级为前端快速导出"兜底选项 |

## 五、AI 生成引擎技术方案

### 输入设计
结构化表单输入优于自由文本：物料类型、尺寸、行业/场景标签、文案要点（分字段：主标题/副标题/正文/联系方式/日期等）、风格偏好（标签化）、可选参考图/品牌素材上传。

**核心论证**：自由文本 prompt 对非设计背景用户不友好（不知道怎么描述"风格"），结构化字段既降低输入门槛，也大幅提升 AI 输出可控性和成功率——这是本产品与"聊天式AI画图"最大的差异化设计。

### 输出：结构化设计对象 Schema 要点
- 顶层：`Canvas`（尺寸、出血、单位mm/px、DPI）→ `Layers`（图层树，支持分组/嵌套）。
- 图层通用属性：`id`、`type`、`position(x,y)`、`size(w,h)`、`rotation`、`zIndex`、`opacity`、锁定状态。
- 图层类型专有属性：
  - `text`：content、fontFamily、fontSize、fontWeight、color、lineHeight、letterSpacing、textAlign、自动换行/自动缩放规则。
  - `image`：src（占位符/AI生成图/图库图/用户上传引用）、fit模式(cover/contain)、滤镜。
  - `shape`：形状类型、填充色、描边、圆角、阴影。
  - `background`：纯色/渐变/图片背景。
  - `icon`：图标库引用+颜色。

**布局方式取舍**：以**绝对定位为主**（每图层精确 x/y/w/h），而非弹性布局。理由：(1) 印刷物料排版对精确对齐/出血要求高，弹性自适应重排逻辑反而增加不可预测性；(2) LLM 更容易稳定生成绝对坐标而非复杂 flex 嵌套关系，AI生成的心智模型更接近"在画布上摆放对象"。图层组内可支持简单对齐/分布辅助属性作为编辑器交互糖，不作为底层数据结构的强约束。

### 生成方式与技术选型
- **文案/布局层**：LLM（如 Claude）直接生成设计 JSON，需精心设计输出 schema 的 few-shot 示例和约束（字号范围、安全边距、图层不重叠基本规则），并做输出后校验（JSON schema 校验 + 版式规则校验，如文字超出画布、对比度是否达标）。
- **图片类图层来源**（三层优先级）：
  1. 用户上传占位（品牌素材、产品图）——最高优先级。
  2. 图库检索（正版素材库API，如 Unsplash/自建企业素材库）——通用场景次优先，风险低成本可控。
  3. AI 文生图填充——用于图库检索不到的特定风格背景/装饰元素，需接入文生图API，评估延迟（比纯文本生成慢很多）与版权风险。
  - **MVP 建议**：以图库检索+用户上传为主，AI文生图作为可选加分项而非核心依赖（可控性和延迟考量）。

### 如何保证生成"好看"（组合策略，非单一依赖LLM审美）
1. **设计规则约束引擎**：把排版设计原理编码为规则库（安全边距、字号层级比例、对齐网格、色彩对比度、留白比例），LLM 生成后经规则引擎校验+自动修正。
2. **模板/版式先验约束**：不让 LLM"从零设计"，而是在预定义的"版式骨架"（已经是专业设计师产出的排版结构，图层内容占位）中做选择+参数填充。这是 Canva/Lovart 类工具的通用做法，大幅降低生成失败率。
3. **前置澄清确认，以信息完整度换生成成功率**：本产品**不采用"多方案生成+用户挑选"来对冲生成质量风险**，而是把风险前移到生成之前——通过结构化追问补全关键信息（文案、素材来源、风格偏好等），确保生成时输入尽可能完整明确，从而支撑"单次生成即可用"的目标。相应地，规则引擎校验+自动修正（策略1）和模板骨架约束（策略2）的可靠性要求比"多方案挑选"模式更高，因为用户看到的就是唯一结果，没有备选项兜底。
4. **色彩/字体系统约束**：预置经过设计验证的配色方案库和字体搭配组合，AI从"安全组合"里选择而非自由生成十六进制色值。

### 澄清确认引擎（Clarify Engine）
这是本产品与常规"一次性生成"工具的核心差异化模块，需要单独设计：
- **输入**：用户已填写的结构化表单 + 自由文本补充说明。
- **处理**：LLM 对照该物料类型的"必需信息清单"（如展板类需要：主标题、核心卖点、活动时间地点、联系方式/二维码、是否有产品图/Logo）做完整性检查，识别缺失或模糊项，生成结构化追问（优先用单选/简答形式而非开放式提问，降低用户回答成本）。
- **输出**：追问以对话形式逐条展示，用户逐项回答或选择"使用默认值/跳过"；单轮追问数量建议上限 3-4 个，避免澄清过程本身成为新的高门槛环节。
- **触发时机**：初次生成前必经；对已有画板做"增量调整"时可视调整幅度决定是否触发简化版澄清（如仅换色不必重新走完整清单）。

### 关键风险点
- LLM 生成的坐标/尺寸数值不稳定，可能图层重叠/溢出/对齐错乱——**必须有生成后自动校验+修正层**，不能假设一次到位。
- 文生图/图库图与整体设计风格不搭调——需要视觉风格一致性约束（如统一色调后处理）。
- 生成延迟：多方案+文生图组合可能导致等待过长，需设定性能预算（如"5秒内出草图预览，20秒内出精修方案"分阶段返回）。
- 版权与合规：图库素材授权范围、AI生成图片可商用性，需法务/采购层面提前确认。

## 六、画布编辑器技术方案

### 数据模型
复用第五节图层 JSON schema 作为编辑器单一数据源（Single Source of Truth）——生成引擎输出与编辑器内部状态是同一份数据结构，避免"生成态"和"编辑态"两套模型转换损耗与不一致风险。

### 前端渲染技术选型
- **Konva.js / Fabric.js（Canvas方案）**：图形操作（拖拽/缩放/旋转/选中框）成熟度高、性能好，但文本渲染和排版能力较弱（富文本、自动换行不如DOM原生），且做HTML导出需额外Canvas→DOM转换层，与"HTML导出低成本"策略冲突。
- **自研 DOM + CSS 方案**：文本渲染天然精细（浏览器原生排版引擎）、样式系统直接复用CSS、**与HTML导出策略高度契合**（渲染态基本等于导出态，序列化成本低）、更容易招到熟悉React/CSS的前端。劣势是需自研"选中/拖拽/多选/对齐吸附/旋转控制点"交互逻辑（有成熟参考实现可借鉴，如 Craft.js、Polotno）。

**结论**：选择**自研 DOM+CSS 方案**（React + 绝对定位容器），放弃 Canvas 类库——渲染层与导出层一致性收益大于自研交互逻辑的额外成本。可参考 Polotno（开源设计编辑器框架）架构思路。

### 编辑操作实现要点
- 选中态：单选/多选、选中框与控制点（缩放/旋转手柄）；画板级选中态与图层级选中态需在渲染层用不同的高亮样式区分（对应第四节4.4/4.5的界面约定）。
- 拖拽：吸附对齐（对齐其他图层边缘/画布中心线）、网格吸附。
- 文本编辑：双击进入编辑态（contentEditable 或受控输入），实时处理自动换行与容器溢出反馈。
- 浮动工具条/上下文属性面板：非常驻侧栏，而是绑定选中图层的位置动态定位渲染（工具条挂载点跟随图层包围盒坐标），根据图层类型渲染不同的精简控件组合，点击"更多"展开完整属性的浮层卡片。
- 图层管理：不设常驻图层树面板，显示/隐藏/锁定/排序（z-index调整）等操作收纳进属性浮层卡片的一个分区，二期视用户反馈评估是否需要独立图层面板。
- 撤销/重做：基于操作历史栈（command pattern），便于精细化撤销粒度。

## 六、导出实现方案

### PNG / PDF
两条技术路径对比：
1. **前端方案**（html2canvas + jsPDF 类似组合）：直接截图当前DOM渲染态。实现简单、无需服务端资源；但**印刷级输出精度和色彩管理不可靠**（html2canvas对复杂CSS/字体渲染有已知兼容性问题，DPI控制、色彩空间、出血线等印刷需求难满足）。
2. **服务端 Headless 渲染方案**（Puppeteer/Playwright 渲染同一套DOM+CSS，截图/打印为PDF）：渲染环境可控、字体一致性有保障、可精确控制DPI/尺寸/出血，适合"印刷可用"场景；但需服务端渲染资源和队列管理，增加基础设施复杂度。

**结论**：目标物料（易拉宝、宣传页）明确有印刷场景，**PDF导出走服务端 Headless 渲染路径**，保证印刷级输出质量；PNG 可前端快速导出低精度预览版+服务端高精度版两档。需与市场部确认"印刷交付质量"是否是硬需求（若只是发朋友圈用，前端方案已够用，成本更低）。

### HTML 导出
编辑器数据模型即结构化DOM渲染状态，导出即"序列化当前渲染态为静态HTML+内联CSS"，技术可行性高、成本低。产出物形态：默认单个自包含HTML文件（内联样式+图片base64/相对路径），便于直接分享打开；同时提供 HTML+CSS+资源文件夹 zip包选项，用于需要托管网页的场景。

### Figma 导出（二期，三条路径对比）
- **路径A：直接生成 .fig 文件**——.fig 是私有二进制格式，Figma 未开放写入规范，逆向生成风险高、维护成本高，随 Figma 更新随时失效，**不推荐**。
- **路径B：Figma REST API 写入**——Figma REST API 目前主要面向"读取"（获取图层/样式/导出图片），**官方REST API 不支持大规模创建/写入设计内容**（写入能力主要通过 Plugin API 在客户端插件环境实现）。
- **路径C：自研 Figma 插件 + Plugin API 桥接**——用户在Figma内安装配套插件，导入本产品导出的结构化JSON，插件调用 Figma Plugin API（`figma.createText()`、`figma.createRectangle()` 等）逐图层还原。**当前唯一现实可行路径**。

**结论**：二期 Figma 导出技术方案锁定为**路径C**，需额外的插件开发和 Figma 插件商店发布流程，工作量与路径A/B有本质不同，规划时不可低估复杂度。

## 七、系统架构简图要点

- **前端（编辑器 Web App）**：左侧无限画布渲染与交互（DOM+CSS结构化图层）、右侧AI对话区（需求输入/澄清确认/生成调整指令的统一入口）、浮动工具条与属性浮层、导出触发入口。技术栈：React + 状态管理（图层树状态、撤销栈、画板/图层选中态）。
- **后端 API 层**：
  - API 网关：鉴权、请求路由、限流（AI生成/导出属重资源请求，需排队/限流保护）。
  - 生成服务：接收对话区确认后的结构化信息→组装Prompt→调用AI服务→接收JSON→跑设计规则校验/修正引擎→返回单一方案结果。
  - 导出服务：接收图层JSON→分发不同导出管线（前端快速导出走客户端；PDF高精度/批量走服务端Headless渲染队列）。
  - 素材/模板管理服务：模板库、风格库、图库检索代理、企业品牌素材库（二期）的CRUD与检索接口。
- **AI 服务层**：
  - LLM 调用封装（Prompt模板管理、结构化输出解析与重试策略）。
  - 文生图调用封装（可选，MVP阶段弱依赖）。
  - 设计规则/校验引擎（AI服务层与后端交界的独立模块，是"让生成结果更好看"的核心逻辑）。
- **存储层**：
  - 设计文件存储（用户图层JSON文档，版本化存储，为二期"历史版本"打基础）。
  - 模板/风格库存储。
  - 素材库存储（图库代理缓存、用户上传素材、品牌素材；二期品牌规范锁定需专门的品牌素材管理表结构）。
  - 导出产物存储（PNG/PDF/HTML文件，含CDN分发）。

## 八、分阶段里程碑规划

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **M1** | 核心生成+编辑器跑通单一物料类目（易拉宝） | 对话式需求输入+澄清确认可跑通并生成1个可用方案；画布支持文字/颜色/位置/图片替换等核心编辑；能导出基础PNG |
| **M2** | 补齐宣传页类目 + PNG/PDF导出完整化 | 宣传页生成质量与易拉宝相当；PDF导出满足印刷级精度（出血/尺寸/DPI）；模板库/风格库上线作兜底 |
| **M3** | 生成质量打磨 + 模板/风格库扩充 + 设计规则引擎完善 | 生成"版式异常率"（溢出/重叠/对比度不达标）降到可接受阈值以下（需定义度量指标）；风格库覆盖常见行业场景；接入生成结果采纳率指标 |
| **M4（二期）** | HTML导出 + 品牌规范锁定 + 协作分享 + 历史版本 | HTML导出可用且渲染一致性达标；品牌规范锁定能让企业客户配置色板/Logo/字体并稳定影响生成结果；基础分享链接可用 |
| **M5（远期）** | Figma插件导出 + 更多物料类目 + 团队协作评审流程 | 涉及独立Figma插件开发线，建议单独排期，不与主编辑器迭代混在同一节奏里 |

**阶段划分逻辑**：M1-M2 先验证"单类目端到端可用"，再横向扩展类目，避免过早在多类目上摊薄打磨生成质量的资源；M3 是专门给"生成质量"留出的打磨阶段——这是容易在计划中被压缩但实际最需要时间的部分，需显式独立成阶段，而非揉进 M1/M2 的"顺便做完"。

## 九、关键风险与挑战

- **AI生成设计"好看"本身是尚未完全解决的技术难题**：LLM 擅长文本/结构化数据生成，对空间关系、视觉平衡、留白美学的判断能力有限。业界（Canva/Lovart等）共同做法是"模板骨架先验约束+规则引擎校验"弥补，不是靠"换个更强模型"就能解决，需团队对此有清醒认知。
- **排版美学保证依赖多层防护而非单点**：设计规则引擎、模板骨架约束、配色字体安全组合库、前置澄清确认——四层策略需同时具备，任一缺失都会导致生成结果"时好时坏、不可预测"，侵蚀用户信任。
- **用户预期管理是产品成败关键**：不能引导用户预期"AI一键生成专业设计师级作品"，应定位为"AI帮你快速起草+你做最后把关式微调"，文案/首次使用引导都需传递这一心智，否则用户第一次生成不满意就会流失；澄清确认+可编辑机制本身就是管理预期的产品设计。
- **结构化数据与最终视觉还原度的落差**：图层JSON到PNG/PDF/HTML/Figma四种渲染管线，天然存在"同一份数据不同管线渲染结果有细微差异"风险（字体渲染差异、CSS特性支持差异、Headless浏览器与用户浏览器渲染差异），需建立"渲染一致性测试"机制，不能假设数据一致=视觉一致。
- **性能与延迟**：单方案生成+澄清确认往返+可能的文生图调用，端到端时延可能达十几秒到几十秒，需设计等待态体验（骨架屏、分批返回、进度提示）缓解焦虑，纯靠"优化到足够快"不现实。
- **版权与合规风险**：图库素材授权、AI文生图产物可商用性和版权归属，需提前找法务/采购介入，直接影响图片来源策略选型（第四节）。
- **印刷交付质量的专业门槛**：市场部同事不熟悉"出血""色彩空间""DPI"等印刷概念，若只把这些参数暴露为表单选项，用户仍会因不懂而选错导致印厂返工。需考虑"智能预设+专业术语翻译成大白话"的交互设计，这是容易被技术团队忽略但直接影响商业落地效果（物料能否真正拿去印刷）的关键点。
